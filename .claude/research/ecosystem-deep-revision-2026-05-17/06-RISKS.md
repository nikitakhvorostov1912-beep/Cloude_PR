# Risks & Mitigations

> Идентификация рисков по каждой рекомендации с конкретными mitigation стратегиями.

## Phase 1 (УЖЕ ПРИМЕНЕНО) — оценка фактических рисков

### R1. Перезаписаны skd-edit, skd-info, form-validate

**Риск:** Локальные правки в этих скиллах потеряны.

**Реальный impact:** Низкий. Из `git status` видно `M` на ВСЕХ 1С-скиллах — это значит правки во всех скиллах массовые (вероятно правка путей, encoding и т.д.). Конкретные правки в skd-edit/skd-info/form-validate не критичны.

**Mitigation:**
- ✅ Бэкапы в `_refresh/local-backups/`
- ✅ Реверс через `cp -r _refresh/local-backups/<skill>.bak .claude/skills/<skill>` (см. 02-APPLIED.md)
- ✅ Можно сравнить через `diff` upstream/local/backup

**Проверка:**
```bash
diff -r _refresh/local-backups/skd-edit.bak .claude/skills/skd-edit
```

### R2. Архивированы hooks/gsd-*

**Риск:** GSD-плагин перестанет работать, если используется.

**Реальный impact:** Нулевой. Проверено: эти hooks НЕ упоминаются в `settings.local.json`. Они были загружены но не подключены.

**Mitigation:** Реверс — `mv _refresh/archived/hooks-gsd/* .claude/hooks/`

### R3. Архивирован connect-apps-plugin

**Риск:** Composio MCP перестанет работать.

**Реальный impact:** Нулевой. Plugin содержал только `commands/setup.md`, не `plugin.json`. По BACKLOG'у Composio MCP заявлен как установленный, но фактически не активирован.

**Mitigation:** Реверс — `mv _refresh/archived/connect-apps-plugin .claude/plugins/`. Если нужен Composio MCP — установить его заново через CC plugin manager.

### R4. METR config переключён на v2

**Риск:** Если v2 тоже невалиден, METR не запустится.

**Реальный impact:** Низкий. По `memory/metr_deep_dive_2026_05_16.md` v2 работает ("Started in 2.9s"). Дополнительно: в этой сессии METR tools загружены через deferred tools (mcp__metr__build_project и др.) — значит работает.

**Mitigation:** Реверс — Edit `.mcp.json` обратно. Хотя по факту v1 не работал — лучше не возвращать.

### R5. +12 obra-скиллов и +4 правил

**Риск:** Конфликт имён с существующими.

**Реальный impact:** Нулевой. Все 12 obra-скиллов имеют префикс `obra-`, никаких конфликтов. 4 правила имеют префикс `1c-`, конфликтов нет.

**Mitigation:** Удалить папки/файлы.

## P1 (НА НЕДЕЛЕ) — потенциальные риски

### R6. feenlace/mcp-1c — установка CFE-расширения в боевую `ut_rt_copy`

**Риск:** CFE-расширение может конфликтовать с существующими (Русский_Транзит и др.) или испортить базу.

**Импакт:** Средний. Расширение от feenlace — read-only API через HTTP-сервис, добавляет endpoint для AI. По описанию не модифицирует данные. Но это всё-таки запись в базу.

**Mitigation:**
1. **Сначала на InfoBase5** (локальная файловая база) — если работает, перенести на `ut_rt_copy`
2. **Бэкап базы перед установкой** — выгрузка CD из Конфигуратора
3. **Тест на копии** `ut_rt_copy_test` если есть
4. **Проверка совместимости:** убедиться что CFE feenlace не конфликтует с Русский_Транзит и существующими расширениями
5. **Реверс:** удалить расширение из Конфигуратора → Конфигурация → Расширения (single click)

**Уровень доверия:** Высокий — ⭐98, активная разработка, открытый код. Но риск install ↔ uninstall цикла на боевую базу.

**Решение:** Сначала проверить на InfoBase5, потом на ut_rt_copy.

### R7. Установка feenlace/mcp-1c — производительность

**Риск:** HTTP-сервис расширения может замедлить базу.

**Импакт:** Низкий. По release notes — лёгкий сервис, read-only запросы.

**Mitigation:**
- Мониторинг загрузки CPU на сервере 1С после установки
- Если медленно — отключить расширение
- Расширение добавляется в общий список, можно отключить в Конфигураторе

### R8. Дублирование функционала между feenlace и 1c-transit

**Риск:** Confusion — два MCP-сервера для одной базы.

**Импакт:** Низкий. Они **дополняют** друг друга:
- 1c-transit (execute_code, MCP Toolkit v1.7.0) — для write-операций, полный доступ
- feenlace/mcp-1c (read-only) — для безопасных queries

**Mitigation:**
- Документировать в `memory/` когда какой использовать
- В `.mcp.json` description'ах указать различия (read-only vs full)

## P2 (НА МЕСЯЦЕ) — потенциальные риски

### R9. Доустановка EDT 2026.1 — миграция workspace

**Риск:** Высокий. Workspace InfoBase5 может не открыться корректно в EDT 2026.1.

**Импакт:** Высокий. Если InfoBase5 окажется битой — потеря локальной разработческой среды.

**Mitigation:**
1. ✅ EDT 2025.2.5 НЕ удалять до подтверждения работы 2026.1
2. ✅ Создать НОВЫЙ workspace для 2026.1: `C:/Users/Khvorostov/eclipse-workspace-2026/`
3. ✅ Import InfoBase5 как НОВЫЙ проект, не открывать существующий workspace
4. ✅ Бэкап `C:/Users/Khvorostov/Documents/InfoBase5/` перед миграцией
5. ✅ Бэкап `.metadata/` со старого workspace
6. Тестовое открытие InfoBase5 в новом workspace
7. Если работает — мигрировать постепенно (один проект за раз)

**Известные проблемы (из MEMORY):**
- `1cedt.exe -data` CLI не работает для 2026.1 — только Cloud Start UI
- Установка через CLI = огрызок 1.6 MB

### R10. EDT-MCP v1.31.1 — несовместимость старого workspace

**Риск:** Плагин v1.31.1 может ожидать структуру workspace от EDT 2026.1 — старые конфиги в .metadata/ могут не загрузиться.

**Импакт:** Средний. Плагин может не запуститься или запуститься с ошибками.

**Mitigation:**
1. Если плагин не работает — откат к v1.26.1 в EDT 2026.1
2. Или откат к EDT 2025.2.5 + EDT-MCP v1.26.1 (текущая комбинация)
3. Документировать что пошло не так в `memory/`

### R11. Контекст промпта раздувается при добавлении инструментов

**Риск:** При добавлении feenlace MCP и других — system prompt растёт. Уже сейчас ~400 skills видно в Skill tool listing.

**Импакт:** Низкий-средний. Каждый MCP добавляет ~10-20 tools в каталог. feenlace добавит 9.

**Mitigation:**
- В `settings.local.json` есть `skillListingMaxDescChars:800` — ограничение длины описания
- Можно отключать неиспользуемые MCP через `.mcp.json` (комментировать)
- При раздувании — рассмотреть P3.7-P3.10 чистку

### R12. EDT 2026.1 миграция — Form.xml vs Form.form формат

**Риск:** EDT 2026.1 может использовать другой формат форм (Form.form вместо Form.xml).

**Импакт:** Высокий. Наши скрипты `deploy-changed.ps1` и `form-edit/compile/validate` работают с Form.xml формате.

**Mitigation:**
1. ✅ DESIGNER (8.3.27) остаётся как fallback для Form.xml
2. ✅ По правилу 3 из CLAUDE.md: "на EDT-проекте InfoBase5 DumpConfigToFiles через DESIGNER может перезаписать формы в формате Configurator (EDT использует Form.form)"
3. Перед миграцией протестировать `cfe-fast-deploy.ps1`/`deploy-changed.ps1` на EDT 2026.1
4. При проблемах — оставить разработку на EDT 2025.2.5 для Form.xml

## P3 (НА ПОТОМ) — низкорисковые операции

### R13. Удаление дубликатов агентов (3× code-reviewer, planner и т.д.)

**Риск:** Сломать workflow если какой-то агент явно вызывается.

**Импакт:** Низкий. Дубли по контексту — наш `code-reviewer` для общих задач, `gsd-code-reviewer` для GSD workflow, `ecc/code-reviewer` для ECC. По факту вызывается тот что в context.

**Mitigation:**
1. Перед удалением — Grep по `.claude/` для упоминаний имён агентов
2. Если упоминаний нет — безопасно удалить
3. Архив в `agents-archive/`
4. Документировать в `INDEX.md`

### R14. Удаление GSD-стека (31 agent + 21 command)

**Риск:** Если фактически используется хотя бы периодически — сломать workflow.

**Импакт:** Зависит от использования.

**Mitigation:**
1. **Проверить транскрипты** через `mcp__ccd_session_mgmt__search_session_transcripts` — поиск "/gsd:" в последних 30 днях
2. Если < 5 вызовов — архивировать в `agents-archive/`
3. Slash-команды `/gsd:*` остаются доступны через namespace
4. Реверс — `mv agents-archive/gsd-* agents/`

### R15. Удаление anthropics-* локальных дублей

**Риск:** Если плагин `anthropic-skills:*` отключится — теряем доступ.

**Импакт:** Низкий — оба источника параллельно работают.

**Mitigation:**
1. Сначала проверить что `anthropic-skills:*` стабильно работает (через `/Skill` invocations)
2. Архивировать локальные `anthropics-*` дубли (не удалять, а в `_refresh/archived/`)
3. Реверс — `mv _refresh/archived/anthropics-* .claude/skills/`

## Общие риски экосистемы

### R16. Локальные правки в 559 файлах перезаписаны при следующем pull

**Риск:** Если делать `git pull` от Nikolay-Shirokov/cc-1c-skills upstream — затрутся локальные правки.

**Импакт:** Высокий.

**Mitigation:**
1. **Не использовать git pull от upstream** — наш репозиторий это С НАШИМИ правками
2. При обновлении upstream — точечное копирование через `_refresh/cc-1c-skills/`
3. Перед любым массовым изменением — `git status` и `git commit`
4. Текущее состояние (559 M файлов) — закоммитить как baseline

### R17. Размер директории `_refresh/`

**Риск:** `_refresh/` содержит клоны и бэкапы — ~30-50 MB.

**Импакт:** Нулевой (диск).

**Mitigation:** После применения изменений и фиксации в git — `rm -rf _refresh/` если не нужно.

**Рекомендация:** оставить до следующего refresh (через 1-2 месяца).

### R18. Безопасность скаченных бинарников

**Риск:** mcp-1c-windows-amd64.v1.6.5.exe — скачан с GitHub releases. Теоретически может быть скомпрометирован.

**Импакт:** Средний (read-only API, но всё же исполняемый файл).

**Mitigation:**
1. ✅ Скачан с официального GitHub release: github.com/feenlace/mcp-1c/releases/download/v1.6.5/mcp-1c-windows-amd64.exe
2. Можно проверить hash если опубликован в release notes
3. Антивирус Windows Defender проверит при запуске
4. Запускается только локально, доступ только к указанной базе

### R19. EDT-MCP HTTP-сервис на localhost:8770

**Риск:** Открытый HTTP-сервис может быть доступен извне (если firewall неправильно настроен).

**Импакт:** Низкий (localhost only по умолчанию).

**Mitigation:** Убедиться что Windows Firewall блокирует входящие на 8770 от внешних адресов.

### R20. Безопасность 1c-transit на localhost:6010

**Риск:** Аналогично R19 — MCP Toolkit на 6010 может execute любой код через execute_code.

**Импакт:** Высокий (full BSL execution).

**Mitigation:**
- ✅ Localhost only — Firewall блокирует внешние подключения
- ✅ Доступен только когда EPF запущен в толстом клиенте
- ✅ Авторизация через сессию пользователя в 1С

## Чеклист безопасности перед действиями

Перед каждым изменением:
- [ ] Git status проверен
- [ ] Файлы для изменения identified
- [ ] Бэкап (`_refresh/backups/`) сделан
- [ ] Реверс-команды документированы
- [ ] Команды установки тестированы на dry-run если возможно
- [ ] Изменения малыми порциями (одна операция = одна проверка)
- [ ] После изменения — smoke-тест
- [ ] При проблемах — реверс

1. **НИКОГДА не запускать git pull от upstream cc-1c-skills/comol/obra** — затрутся локальные правки
2. **НИКОГДА не устанавливать в ut_rt_copy без бэкапа** — даже read-only расширения
3. **НИКОГДА не удалять EDT 2025.2.5 до подтверждения работы 2026.1**
4. **НИКОГДА не применять массовые операции без `git status` и commit**
5. **НИКОГДА не использовать --force в git push/checkout без причины**
6. **НИКОГДА не использовать MCP35** (CRUD на прод опасен)
7. **НИКОГДА не устанавливать community форки от unknown authors** без аудита
