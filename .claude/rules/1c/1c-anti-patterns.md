# 1С Антипаттерны и рекомендации по производительности

> Confidence scoring: ≥75 для code review, ≥50 для архитектурного ревью.
> Источник: comol/ai_rules_1c + 1c-rules.md (адаптировано).

## Critical антипаттерны (исправить обязательно)

### 1. Запрос в цикле (Query in Loop)
```bsl
// ПЛОХО: O(n) запросов к БД
Для Каждого Строка Из Таблица Цикл
    Запрос.УстановитьПараметр("Ссылка", Строка.Контрагент);
    РезультатЗапроса = Запрос.Выполнить();
КонецЦикла;

// ХОРОШО: один пакетный запрос
СписокСсылок = Таблица.ВыгрузитьКолонку("Контрагент");
Запрос.УстановитьПараметр("Список", СписокСсылок);
// Запрос с "В (&Список)"
```

### 2. Обращение через точку к реквизитам (Direct Attribute Access)
```bsl
// ПЛОХО: загружает весь объект
ИНН = Контрагент.ИНН;

// ХОРОШО: только нужный реквизит
ИНН = ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Контрагент, "ИНН");

// ХОРОШО: несколько реквизитов пакетом
Реквизиты = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Контрагент, "ИНН, КПП, Наименование");
```

### 3. Подзапрос в SELECT (Subquery in SELECT)
```bsl
// ПЛОХО: N+1 — подзапрос выполняется для каждой строки
"ВЫБРАТЬ
|    Д.Ссылка,
|    (ВЫБРАТЬ СУММА(ЗаказыТЧ.Количество)
|     ИЗ Документ.ЗаказПокупателя.Товары КАК ЗаказыТЧ
|     ГДЕ ЗаказыТЧ.Ссылка = Д.Ссылка) КАК ОбщееКоличество
|ИЗ Документ.ЗаказПокупателя КАК Д"

// ХОРОШО: ЛЕВОЕ СОЕДИНЕНИЕ с предварительной группировкой
```

## High антипаттерны

### 4. Фильтр виртуальной таблицы в WHERE
```bsl
// ПЛОХО: фильтр ПОСЛЕ загрузки всей таблицы
"ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки() КАК Остатки
|ГДЕ Остатки.Склад = &Склад"

// ХОРОШО: фильтр в параметрах ВТ
"ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(, Склад = &Склад) КАК Остатки"
```

### 5. Отсутствие ПЕРВЫЕ N при проверке существования
```bsl
// ПЛОХО: загружает всю таблицу
"ВЫБРАТЬ Ссылка ИЗ Справочник.Контрагенты ГДЕ ИНН = &ИНН"

// ХОРОШО
"ВЫБРАТЬ ПЕРВЫЕ 1 Ссылка ИЗ Справочник.Контрагенты ГДЕ ИНН = &ИНН"
```

### 6. Множественные серверные вызовы
```bsl
// ПЛОХО: 3 round-trip
&НаКлиенте
Процедура ЗаполнитьФорму()
    Контрагент = ПолучитьКонтрагента();        // 1 вызов
    Валюта = ПолучитьВалюту();                 // 2 вызов
    Курс = ПолучитьКурс(Валюта);               // 3 вызов
КонецПроцедуры

// ХОРОШО: 1 round-trip
&НаСервереБезКонтекста
Функция ПолучитьДанныеФормы()
    Результат = Новый Структура("Контрагент, Валюта, Курс");
    // заполнить всё разом
    Возврат Результат;
КонецФункции
```

### 7. &НаСервере вместо &НаСервереБезКонтекста
```bsl
// ПЛОХО: передаёт всю форму на сервер
&НаСервере
Процедура ЗаполнитьСписокНаСервере()
    // использует только 1 параметр формы
КонецПроцедуры

// ХОРОШО: передаём только нужное
&НаСервереБезКонтекста
Процедура ЗаполнитьСписок(Организация)
КонецПроцедуры
```

## Medium антипаттерны

### 8. O(n²) вложенные циклы (поиск в коллекции)
```bsl
// ПЛОХО: O(n²)
Для Каждого Строка1 Из Таблица1 Цикл
    Для Каждого Строка2 Из Таблица2 Цикл
        Если Строка1.Ключ = Строка2.Ключ Тогда ...

// ХОРОШО: O(n) — индекс через Соответствие
Индекс = Новый Соответствие;
Для Каждого Строка Из Таблица2 Цикл
    Индекс.Вставить(Строка.Ключ, Строка);
КонецЦикла;
Для Каждого Строка1 Из Таблица1 Цикл
    Строка2 = Индекс.Получить(Строка1.Ключ);
```

### 9. Глубокая вложенность > 4 уровней
```bsl
// ПЛОХО: 5+ уровней вложенности
Если А Тогда
    Для Каждого Б Из ... Цикл
        Если В Тогда
            Попытка
                Если Г Тогда
                    // 5-й уровень

// ХОРОШО: ранний возврат + выделение в функции
Если НЕ А Тогда Возврат; КонецЕсли;
ОбработатьВложенноеДействие(Б, В, Г);
```

### 10. Отсутствие кеширования в цикле
```bsl
// ПЛОХО: одинаковое вычисление N раз
Для Каждого Строка Из Таблица Цикл
    Курс = РегистрыСведений.КурсыВалют.ПолучитьПоследнее(Дата, Новый Структура("Валюта", Валюта));
КонецЦикла;

// ХОРОШО: вычислить один раз до цикла
Курс = РегистрыСведений.КурсыВалют.ПолучитьПоследнее(Дата, Новый Структура("Валюта", Валюта));
Для Каждого Строка Из Таблица Цикл
    // используем Курс
КонецЦикла;
```

## Архитектурные антипаттерны

### Big Ball of Mud
Запутанные зависимости без чёткой архитектурной структуры. Признаки: нет разделения слоёв, всё зависит от всего, невозможно изолировать для тестирования.

### God Module
Общий модуль с сотнями процедур разной ответственности. Решение: разбить на модули по домену (ОбщегоНазначения → отдельные модули по функциям).

### Tight Coupling
Прямые вызовы между несвязанными подсистемами вместо подписок/событий. Решение: подписки на события объектов, общие интерфейсы.

### Copy-Paste Architecture
Дублированная бизнес-логика в нескольких местах. Решение: вынести в экспортные методы общих модулей.

### Premature Optimization
Усложнение кода ради производительности без профилирования. Сначала — читаемость, потом — оптимизация с измерениями.

## AI-специфичные антипаттерны генерации (Critical)

Эти ошибки LLM делают на BSL чаще всего — проверять при ревью КАЖДОГО AI-сгенерированного блока.

### A1. Тернарный оператор `?(условие, A, B)`
LLM генерит несмотря на запрет в правилах. Заменять на `Если...Тогда...Иначе...КонецЕсли`.
Поиск: `Grep '\?\('`.

### A2. `Сообщить()` вместо SSL-методов
AI пишет `Сообщить("текст")` (платформа 8.1 паттерн). Корректно: `ОбщегоНазначения.СообщитьПользователю()` (сервер) или `ОбщегоНазначенияКлиент.СообщитьПользователю()` (клиент).
Поиск: `Grep 'Сообщить\("'`.

### A3. Забывание `&НаСервереБезКонтекста`
По умолчанию AI пишет `&НаСервере` для всех серверных методов формы. Если метод не читает/не пишет реквизиты формы — обязательно `&НаСервереБезКонтекста`.
Поиск: `Grep '^&НаСервере$'`.

### A4. Доступ через точку к реквизитам ссылки
`ИНН = Контрагент.ИНН` — загружает весь объект. AI забывает, особенно в циклах. Заменять на `ОбщегоНазначения.ЗначениеРеквизитаОбъекта()` или `.ЗначенияРеквизитовОбъекта()`.

### A5. Запросы без `ВТ_`-префикса для временных таблиц
AI генерит `ПОМЕСТИТЬ Товары`. Корректно: `ПОМЕСТИТЬ ВТ_Товары`. Соглашение проекта.

### A6. Лишний `Попытка/Исключение` для невозможных сценариев
LLM добавляет try/except «на всякий случай» вокруг чтения ссылки или вызова стандартного API. Защитные блоки только для **ожидаемых** исключений (сетевые таймауты, файловый I/O, парсинг JSON).

### A7. Синхронные диалоги `Вопрос()` / `Предупреждение()`
AI генерит модальные диалоги несмотря на платформу 8.3.18+. Использовать `ПоказатьВопрос()` с `ОписаниеОповещения` или `Асинх`-методы.

### A8. Хардкод имени пользователя/пути/учётной записи
AI часто пишет `Пользователь = "Администратор"` или абсолютный путь `C:\Temp\file.txt`. Использовать `ПараметрыСеанса`, временные файлы через `ПолучитьИмяВременногоФайла()`, конфиг через константы.

### A9. Игнор `// Доработка START/END` маркеров
AI правит чужой/типовой код без обёртки в маркеры. Обязательно при работе в `src/cfe/` с заимствованным методом.

### A10. Магические числа в логике
LLM генерит `Если КодОшибки = 47 Тогда`. Выносить в именованные константы или Перечисления.

### A11. `ТекущаяДата()` вместо `ТекущаяДатаСеанса()`
LLM привычно пишет `ТекущаяДата()` — нарушает TZ сессии и кластер.
Поиск: `Grep 'ТекущаяДата\(\)'`.

## Чек-лист ревью AI-сгенерированного кода

После генерации **обязательно** прогнать:

1. **BSL Language Server** (`/bsl-lint`) — синтаксис + правила
2. **Поиск антипаттернов** A1–A11 через `Grep` по характерным паттернам
3. **Проверка имён через MCP `bsl-context`** — нет коллизий с глобальным контекстом, методы существуют
4. **Smoke-тест** через `mcp-1c.execute_code` — открыть форму / запустить процедуру в живой 1С
5. **Если бизнес-логика** — YAxUnit тест через `1c-test-runner`
