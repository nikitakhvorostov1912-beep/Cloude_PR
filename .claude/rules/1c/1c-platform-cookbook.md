# 1С Platform Cookbook — готовые решения типичных задач

> Источник: comol/ai_rules_1c platform-solutions.md (адаптировано).
> Кейсбук типовых проблем платформы с проверенными решениями.

## 1. Проверка заполненности

```bsl
// ПРАВИЛЬНО — универсально для всех типов
Если НЕ ЗначениеЗаполнено(Контрагент) Тогда ...

// НЕПРАВИЛЬНО — false positives для пустых ссылок
Если Контрагент = Неопределено Тогда ...
Если Контрагент = Null Тогда ...
```

## 2. Длительные операции (фоновые задачи)

```bsl
// ПРАВИЛЬНО: через ДлительныеОперации — UI-уведомления, отмена, сериализация
ПараметрыФункции = Новый Структура;
ПараметрыФункции.Вставить("Организация", Организация);

ДлительнаяОперация = ДлительныеОперации.ВыполнитьФункцию(
    "МойМодуль.МояДлительнаяФункция", ПараметрыФункции
);

// НЕ напрямую: ФоновыеЗадания.Выполнить() — нет UI-уведомлений
```

## 3. Временное хранилище

```bsl
// ПРАВИЛЬНО: платформенные глобальные функции (не методы объекта!)
АдресВХранилище = ПоместитьВоВременноеХранилище(ДанныеДляПередачи, УникальныйИдентификатор);
Данные = ПолучитьИзВременногоХранилища(АдресВХранилище);

// НЕ: ВременноеХранилище.Поместить() — объект не существует
```

## 4. Транзакции в обработчиках записи

```bsl
// НЕ открывать вложенные транзакции в ПередЗаписью/ПриЗаписи
// Платформа уже управляет внешней транзакцией!

// ПЛОХО
Процедура ПередЗаписью(Отказ)
    НачатьТранзакцию();  // НЕ НУЖНО — уже в транзакции
    // ...
КонецПроцедуры

// ХОРОШО — использовать существующую транзакцию
Процедура ПередЗаписью(Отказ)
    // просто работаем в контексте существующей транзакции
КонецПроцедуры
```

## 5. Копирование объектов

```bsl
// Таблица значений
НоваяТЗ = ИсходнаяТЗ.Скопировать();

// Документ — создаём новый, очищаем системные поля
НовыйДокумент = Документы.МойДокумент.СоздатьДокумент();
ЗаполнитьЗначенияСвойств(НовыйДокумент, ИсходныйДокумент);
НовыйДокумент.Номер = "";       // очистить
НовыйДокумент.Дата = ТекущаяДатаСеанса();
НовыйДокумент.Проведен = Ложь;  // сбросить статус
```

## 6. Время на сервере

```bsl
// ВСЕГДА используй ТекущаяДатаСеанса() — учитывает TZ сессии и кластер
ТекущееВремя = ТекущаяДатаСеанса();

// НЕ ТекущаяДата() — UTC системы, без TZ сессии
```

## 7. Поиск в коллекции (O(1) vs O(n))

```bsl
// ДЛЯ > 100 ЭЛЕМЕНТОВ или в циклах — всегда Соответствие
// Строить индекс ДО цикла, не внутри

// ПЛОХО: O(n²) — Найти() внутри цикла
Для Каждого Строка Из БольшаяТЗ Цикл
    НайденнаяСтрока = ДругаяТЗ.Найти(Строка.Ключ, "Ключ");

// ХОРОШО: O(n) — Соответствие
ИндексДругойТЗ = Новый Соответствие;
Для Каждого Стр Из ДругаяТЗ Цикл
    ИндексДругойТЗ.Вставить(Стр.Ключ, Стр);
КонецЦикла;

Для Каждого Строка Из БольшаяТЗ Цикл
    НайденнаяСтрока = ИндексДругойТЗ.Получить(Строка.Ключ);
```

## 8. Внешние компоненты

```bsl
// ПРАВИЛЬНО: асинхронно, без блокировки UI
НачатьПодключениеВнешнейКомпоненты(
    Новый ОписаниеОповещения("ПослеПодключенияКомпоненты", ЭтотОбъект),
    "ИмяМакета",
    ЭтаФорма,
    ТипВнешнейКомпоненты.Native
);

// НЕ: ПодключитьВнешнююКомпоненту() — блокирует UI, не работает в веб-клиенте
```

## 9. Управляемые блокировки при проведении

```bsl
// ОБЯЗАТЕЛЬНО: установить ДО чтения остатков
Блокировка = Новый БлокировкаДанных;
ЭлементБлокировки = Блокировка.Добавить("РегистрНакопления.ТоварыНаСкладах");
ЭлементБлокировки.УстановитьЗначение("Склад", Склад);
ЭлементБлокировки.Режим = РежимБлокировкиДанных.Исключительный;
Блокировка.Заблокировать();

// Читать остатки ПОСЛЕ блокировки
Остатки = РегистрыНакопления.ТоварыНаСкладах.Остатки(Дата, Отбор);

// Порядок блокировок — одинаковый во ВСЕХ документах (предотвращает дедлок)
```

## 10. Проверка перед записью

```bsl
// ПРАВИЛЬНО: ОтказатьсяОтЗаписи через Отказ
Процедура ПередЗаписью(Отказ)
    Если НЕ ЗначениеЗаполнено(Реквизит) Тогда
        ОбщегоНазначения.СообщитьПользователю(
            НСтр("ru='Реквизит не заполнен'"),
            ЭтотОбъект,
            "Реквизит"
        );
        Отказ = Истина;
    КонецЕсли;
КонецПроцедуры
```

## YAxUnit Mocking (25.12+)

Платформа YAxUnit 25.12 (загружен в InfoBase5) поддерживает мокинг через `ЮТМоки`. Применять **точечно** — на границах системы (HTTP/файлы/UUID/время), не на бизнес-логике.

### Mock UUID — детерминированные тесты

```bsl
ОжидаемыйУИД = "12345678-1234-1234-1234-123456789012";
ЮТМоки.Подменить(ЭтотОбъект, "НовыйУникальныйИдентификатор",
    Новый ОписаниеТипов("УникальныйИдентификатор"), ОжидаемыйУИД);
```

Когда: проверка идемпотентности обмена, payload JSON со стабильным UUID.

### Mock методов платформы

```bsl
// Подмена ТекущаяДатаСеанса (детерминированные тесты с датами)
ЮТМоки.ПодменитьМетод("ОбщегоНазначения", "ТекущаяДатаСеанса",
    Дата(2026, 5, 9, 10, 0, 0));

// Подмена HTTP-соединения для интеграции (Sigma)
ЮТМоки.ПодменитьМетод("HTTPСоединение", "ОтправитьДляОбработки",
    Новый Структура("КодСостояния, ТелоОтвета", 200, "{""ok"":true}"));
```

Когда: блокирующие API (HTTP, файлы), интеграции, таймауты.

### Mock внешнего клиента

```bsl
ЮТМоки.ПодменитьМетод("СигмаКлиент", "ВыполнитьЗапрос",
    Новый Структура("Код, Тело", 404, ""));
```

Когда: error paths (timeout, 5xx, rate limit) без реальных вызовов.

### Правила

- Одна граница — один mock. Нагромождение = тест проверяет реализацию.
- В `ПослеКаждогоТеста()` — обязательно `ЮТМоки.СброситьВсе()`.
- НЕ мокать `ОбщегоНазначения.*` для бизнес-логики (только границы: ТекущаяДатаСеанса, ПолучитьИмяВременногоФайла, НовыйУникальныйИдентификатор).
- Для Русский_Транзит — приоритет: Sigma API, ETD endpoint, файлы ГТД-сканов.
