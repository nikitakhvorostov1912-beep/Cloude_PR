# Стандарты модуля управляемой формы 1С

> Источник: comol/ai_rules_1c dev-standards-forms.md (адаптировано для проекта Русский Транзит).
> Используется агентами `1c-code-writer`, `1c-code-reviewer`, `1c-code-architect`.

## 1. Обязательная структура областей модуля формы

Порядок областей строго фиксирован:

```bsl
#Область ОписаниеПеременных
// Переменные формы (минимум — только когда действительно нужны)
#КонецОбласти

#Область ОбработчикиСобытийФормы
// ПриСозданииНаСервере, ПриОткрытии, ПередЗакрытием, ПриЗакрытии
#КонецОбласти

#Область КомандыФормы
// Обработчики команд формы (&НаКлиенте, &НаСервере, &НаСервереБезКонтекста)
#КонецОбласти

#Область ОбработчикиСобытийЭлементов
// ПриИзменении, НачалоВыбора, ОбработкаВыбора и т.д.
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
// Внутренние вспомогательные процедуры и функции
#КонецОбласти
```

## 2. Директивы компилятора: когда что использовать

| Директива | Когда использовать |
|---|---|
| `&НаКлиенте` | Реакция на UI-события, навигация, открытие форм |
| `&НаСервере` | Только когда нужен контекст формы (чтение/запись реквизитов формы из серверного кода) |
| `&НаСервереБезКонтекста` | Всегда предпочтительнее — меньше данных передаётся, нет зависимости от контекста формы |
| `&НаКлиентеНаСервере` | Только для кода, работающего на обоих уровнях (крайне редко) |

**Правило:** Если метод не читает/не пишет реквизиты формы напрямую — использовать `&НаСервереБезКонтекста`.

## 3. Обязательные обработчики

### ПриСозданииНаСервере
```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)

    // 1. Установить функциональные опции / ограничения
    // 2. Заполнить реквизиты по умолчанию
    // 3. Настроить состояние элементов формы
    // Не делать тяжёлых запросов здесь — откладывать на ПриОткрытии

КонецПроцедуры
```

### Обработчики кнопок
```bsl
// Кнопки — всегда на клиенте, тяжёлая работа — выносить на сервер
&НаКлиенте
Процедура ВыполнитьДействие(Команда)
    ВыполнитьДействиеНаСервере();
КонецПроцедуры

&НаСервереБезКонтекста
Процедура ВыполнитьДействиеНаСервере()
    // Бизнес-логика
КонецПроцедуры
```

## 4. Работа с реквизитами формы

### ЗАПРЕЩЕНО — прямое изменение данных объекта через форму на сервере
```bsl
// НЕПРАВИЛЬНО — объект читается неявно
&НаСервере
Процедура НеПравильноНаСервере()
    Объект.Реквизит = "значение";  // Загружает весь объект + контекст формы
КонецПроцедуры
```

### ПРАВИЛЬНО — через параметры
```bsl
&НаСервереБезКонтекста
Функция ПолучитьДанные(Параметр1, Параметр2)
    // Явные входные параметры, явный возврат
    Возврат РезультатВычислений;
КонецФункции

&НаКлиенте
Процедура ОбновитьДанные()
    Данные = ПолучитьДанные(Объект.Реквизит1, Объект.Реквизит2);
    Объект.Результат = Данные;
КонецПроцедуры
```

## 5. Программное управление элементами формы

```bsl
// Изменять свойства элементов только по необходимости, не дублировать XML-настройки
Элементы.Реквизит1.Доступность = ЕстьПраваНаРедактирование;
Элементы.КнопкаСохранить.Видимость = НеНовый;

// Для динамических колонок таблицы — через НастройкиТипа
НовыйЭлемент = Элементы.Добавить("КолонкаСумма", Тип("ПолеФормы"), Элементы.ТаблицаТЧ);
НовыйЭлемент.Вид = ВидПоляФормы.ПолеВвода;
НовыйЭлемент.ПутьКДанным = "Объект.ТЧ.Сумма";
```

## 6. Заполнение ТЧ из запроса

```bsl
&НаСервереБезКонтекста
Функция ПолучитьТабличнуюЧасть(Ссылка)
    Запрос = Новый Запрос;
    Запрос.Текст =
    "ВЫБРАТЬ
    |   ТЧ.Номенклатура КАК Номенклатура,
    |   ТЧ.Количество   КАК Количество,
    |   ТЧ.Сумма        КАК Сумма
    |ИЗ
    |   Документ.РеализацияТоваровУслуг.Товары КАК ТЧ
    |ГДЕ
    |   ТЧ.Ссылка = &Ссылка";
    Запрос.УстановитьПараметр("Ссылка", Ссылка);
    Возврат Запрос.Выполнить().Выгрузить();
КонецФункции

// На клиенте — загрузить результат в ТЧ формы
&НаСервере
Процедура ЗагрузитьТЧНаСервере()
    ТЧДанные = ПолучитьТабличнуюЧасть(Объект.Ссылка);
    Объект.Товары.Загрузить(ТЧДанные);
КонецПроцедуры
```

## 7. Асинхронные диалоги (платформа 8.3.18+)

```bsl
// ЗАПРЕЩЕНО (платформа 8.3.18+)
Ответ = Вопрос("Провести документ?", РежимДиалогаВопрос.ДаНет);
Если Ответ = КодВозвратаДиалога.Да Тогда ...

// ПРАВИЛЬНО — асинхронный вопрос
&НаКлиенте
Процедура ПровестиДокумент(Команда)
    ПоказатьВопрос(
        Новый ОписаниеОповещения("ПослеВопросаОПроведении", ЭтотОбъект),
        "Провести документ?",
        РежимДиалогаВопрос.ДаНет
    );
КонецПроцедуры

&НаКлиенте
Процедура ПослеВопросаОПроведении(Ответ, ДопПараметры) Экспорт
    Если Ответ <> КодВозвратаДиалога.Да Тогда
        Возврат;
    КонецЕсли;
    ПровестиДокументНаСервере();
КонецПроцедуры
```

## 8. Антипаттерны модуля формы

### Critical
- **Запрос в ПриИзменении** — блокирует UI. Отложить в фоновое задание или кешировать
- **Прямое изменение ТЧ через цикл на сервере без контекста** — нарушает синхронизацию
- **Выполнить() в модуле формы** — ЗАПРЕЩЕНО

### High
- **Глобальные переменные формы** — использовать только когда данные нужны в нескольких методах и нет смысла передавать через параметры
- **&НаСервере вместо &НаСервереБезКонтекста** для логики без доступа к реквизитам
- **Синхронные вопросы/диалоги** — заменять на асинхронные (8.3.18+)

### Medium
- **Повторные серверные вызовы** в одном обработчике — объединить в один вызов, возвращающий Структуру
- **Нарушение порядка областей** — снижает читаемость, усложняет ревью

## 9. Передача данных клиент ↔ сервер

```bsl
// Правило: передавай минимально необходимое
// Плохо — передаёт весь объект через контекст формы
&НаСервере
Процедура РассчитатьНаСервере()
    Сумма = Объект.Количество * Объект.Цена;
    Объект.Сумма = Сумма;
КонецПроцедуры

// Хорошо — явные параметры
&НаСервереБезКонтекста
Функция РассчитатьСумму(Количество, Цена)
    Возврат Количество * Цена;
КонецФункции

&НаКлиенте
Процедура ЦенаПриИзменении(Элемент)
    Объект.Сумма = РассчитатьСумму(Объект.Количество, Объект.Цена);
КонецПроцедуры
```

## AI-промпт паттерны для модуля формы

LLM (Claude/Sonnet/GPT) часто генерит управляемые формы криво. Form.xml — мёртвая зона AI (см. `1c-ai-collaboration.md`). Для UI-логики модуля формы — использовать промпт-шаблон C из скилла `1c-prompt-patterns`:

```
Role: разработчик UI 1С (управляемые формы).
Task: <описание>.
Constraints:
  - Минимальная ширина групп ≥ 1280px (8.5-совместимость)
  - Никаких декораций для заголовков полей (ломает автофокус)
  - &НаСервереБезКонтекста где не нужны реквизиты формы
  - Никаких синхронных диалогов (ОписаниеОповещения / Асинх)
  - Никакой бизнес-логики в модуле формы — только UI
Format:
  - JSON DSL для form-compile (не XML)
  - Модуль формы: разделение на области ОбработчикиСобытийФормы / КомандыФормы / СлужебныеПроцедурыИФункции
```

Типичные AI-ошибки именно в модуле формы:
- Бизнес-логика прямо в обработчиках элементов (вместо вызова общего модуля)
- `&НаСервере` вместо `&НаСервереБезКонтекста` для расчётов
- Прямое изменение `Объект.*` через цикл на сервере (вместо явных параметров)
- `Вопрос()/Предупреждение()` синхронные — вместо `ПоказатьВопрос()` асинхронных
- Пропуск порядка областей (часто всё в одну кучу)

После генерации — Grep по A1-A11 (`rules/1c/1c-anti-patterns.md`).
