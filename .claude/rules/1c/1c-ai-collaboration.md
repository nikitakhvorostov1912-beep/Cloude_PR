# Когда AI помогает / ломает в 1С-разработке

> Правило для агентов и пользователя: **где AI ускоряет, где замедляет, где портит**.
> Источник: matakov.com (правило 3 итераций), habr 975926 (DAC), habr 924116 (comol85), кейс APIСигма 06.05.2026.

## Когда AI помогает (1-2 итерации, ROI x3+)

| Тип задачи | Пример | Метрика |
|-----------|--------|---------|
| **Анализ существующего кода** | Восстановить назначения 12 SQL-запросов в обработке 13K строк | 6 ч ручного → 2 ч с AI (Матаков) |
| **Документирование** | Описание экспортных методов из подписей | мгновенно |
| **Поиск зависимостей** | Все вызовы метода через find_references | мгновенно |
| **Простые модификации** | Добавить колонку в ТЧ, добавить отбор в запрос | 1 раунд |
| **Конвертация** | Старый запрос → новый формат, curl → BSL HTTP-запрос | 1 раунд |
| **Промпт-инжиниринг тестов** | YAxUnit happy-path по описанию | 1-2 раунда |
| **Сравнения** | Diff двух конфигураций / двух версий метода | мгновенно |

## Когда AI требует 3+ итерации (используй с экспертом)

| Тип задачи | Признак | Стратегия |
|-----------|---------|-----------|
| **Новая обработка с нуля** | 200+ строк бизнес-логики | Дробить на vertical slices, каждый <50 строк |
| **Сложная бизнес-логика** | Неявные правила учётной политики | Сначала Spec.md (см. 1c-feature-dev Phase 0) |
| **Оптимизация запросов** | Блокировки + индексы + временные таблицы | Сначала EXPLAIN, потом AI с конкретным планом |
| **CFE-перехватчики типовых** | Подписки на события, ПередЗаписью | Архитектор → AI → ревью человеком |
| **RLS / роли** | Шаблоны ограничения доступа | Чек-лист правил перед, тестирование с разными пользователями |

## Когда AI ломает (не использовать как primary)

| Тип задачи | Почему ломает | Альтернатива |
|-----------|---------------|--------------|
| **XML-форм Form.xml вручную** | Кривая структура, забывает `<LabelDecoration>`, ломает редактирование в EDT | DESIGNER → DumpCfg → AI правит JSON через `form-edit` |
| **Меняет логику переводов БСП** | Не понимает контекста многоязычности | Прямая правка |
| **Генерит запросы под высокую конкурентность** | Не учитывает блокировки и порядок | Архитектор пишет блокировки, AI — только тело запроса |
| **Декомпиляция типового по защищённому коду** | Запрещено лицензией 1С + AI «придумает» | Не делать вообще |

## Правило 3 итераций (Матаков)

Если задача не закрыта за **3 раунда** уточнений с экспертом — **переписать вручную**.

**Признаки исчерпания AI-цикла:**
- Одни и те же ошибки повторяются в новых формулировках («забыл проверку», «теперь забыл другую»)
- Каждый раунд чинит одно — ломает другое
- Эксперт уже знает решение лучше чем формулировка в ТЗ → задача **недоопределена**, надо вернуться к Spec
- AI начинает «фантазировать» имена методов / реквизитов / типов

**Что делать после 3 раундов:**
1. Стоп AI-цикл
2. Переформулировать задачу в Spec.md явно (acceptance criteria, out of scope)
3. Если переформулировка не помогла — писать руками
4. AI оставить для парных задач: тесты, документация, ревью своего же ручного кода

## Кейсы (с цифрами)

### Кейс 1 — Анализ обработки (Матаков)
- **Задача:** 13 378 строк, восстановить логику 12 SQL-запросов
- **Без AI:** 6+ часов ручного reverse-engineering
- **С Claude:** 2 часа, найдено 12 запросов с назначениями + забытые ПВХ-настройки
- **ROI:** x3
- **Урок:** анализ — самая прибыльная зона AI

### Кейс 2 — Новая обработка (Матаков)
- **Задача:** написать новую обработку по описанию
- **С Claude:** 3 итерации до синтаксически валидного кода, логика всё равно не та
- **Решение:** переписать вручную
- **Урок:** генерация с нуля без чёткого Spec — путь в тупик

### Кейс 3 — Оптимизация через Gemini (Бычков)
- **Задача:** обработка выгрузки с циклами
- **С Gemini:** предложила XPath вместо ручных циклов
- **Результат:** x2 скорость на этой задаче
- **Урок:** AI знает паттерны платформы, к которым человек не приходит сам

### Кейс 4 — APIСигма (06.05.2026, мой)
- **Задача:** EPF не запускается — ошибка в Module.bsl
- **Что не сработало:** 5 туров поиска «другой версии файла» вместо чтения ошибки
- **Что сработало:** прочитать stack trace, найти строку, исправить
- **Урок:** не пивотить молча на смену поиска при наличии конкретной ошибки. Брутальная честность ↔ пушбэк.

## Сигналы качества AI-сессии

**Сессия успешна если:**
- ≤ 3 итерации до зелёного теста / smoke
- AI признаёт незнание вместо фантазии
- В коде нет антипаттернов из `1c-anti-patterns.md` секция A1-A11
- Эксперт может объяснить КАЖДУЮ строку результата

**Сессия провалена если:**
- > 3 итерации без приближения к решению
- AI «уверенно» использует несуществующие методы платформы
- Каждый round разрушает предыдущий
- Эксперт начинает писать сам параллельно

## Юридические границы (важно для ERP/УТ)

- **НЕ отправлять в Anthropic API** код типовых конфигураций без правки лицензионного соглашения с пользователем
- **НЕ декомпилировать** защищённый код через AI — нарушение лицензии 1С
- **Конфиденциальность ПД** — реальные данные базы (контрагенты, паспорта, договоры) не передавать в облачный AI; работать на анонимизированных копиях

> Подробного публичного юридического анализа на 2026 год нет — пробел в индустрии.
