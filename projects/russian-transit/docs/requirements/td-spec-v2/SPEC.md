# SPEC v2 — Загрузка реестра ТД (полный рефакторинг 2026-05-01)

> Снапшот архитектуры на 2026-05-01.
> Заменяет SPEC v1 в части реализации (бизнес-цели не меняются).
> Изменения относительно v1 описаны в разделе «Что изменилось».

---

## 1. Цель обработки одной фразой

> Пользователь раз в сутки выгружает из Сигмы «Отчёт по журналу ЭТД» (CSV)
> и нажимает в 1С одну кнопку. Обработка автоматически:
> 1) Помечает уже существующие документы поручительства как **Комплекс**
>    (мы оформляли и обеспечение, и ТД).
> 2) Создаёт новые документы для тех ТД, которых ещё нет в 1С —
>    они идут в учёт как **«Только ТД»** (мы оформляли только декларацию,
>    обеспечение давал другой брокер).

## 3. Алгоритм классификации (CSV-driven 1:1 V3.1, без изменений с 2026-04-29)

```
Для КАЖДОЙ строки CSV (без дедупликации):
  — пустой НомерДДПТД (col #8)         → НоваяТД (создать ОПП по РегНомеруТД)
  — DDP найден в БД (по ТЧ.НомерГТД)   → Комплекс (обогатить существующую ТЧ)
  — DDP не найден, но матч по
    ТС+Декларант+Дата                  → Комплекс (fallback Шаг 2)
  — DDP не найден совсем               → НоваяТД (создание нового ОПП)

ТолькоОбеспечение в этой обработке НЕ генерируется автоматически.
Категория есть, но проставляется через другую обработку (анализ DDP без CSV-пары).
```

**Важно:** дубликаты НомерДДПТД в CSV — это бизнес-кейс «один ДДП на 4-28 ТД».
Каждая строка CSV получает своё предложение. Дедуп дал бы потерю ТД.

## 4. Что должна заполнять обработка при «Применить»

### 4.1. Категория «Комплекс» — обогащение существующего ОПП

В найденной строке ТЧ ДанныеДокументов:
- `ТипУчета` ← `Перечисления.ТипыУчетаКлиентов.Комплекс`
- `ДатаОформления` ← `СтрокаCSV.ДатаВыпуска` (если в ТЧ было пусто)
- `КоличествоУникальныхКодовТНВЭД` ← `СтрокаCSV.КоличествоКодовТНВЭД`

**НОВОЕ в v2 — в шапке документа** (только если поля были пусты):
- `Контрагент` ← вычисленный по email/ИНН/подразделению из CSV
- `ИННКонтрагента` ← `СтрокаCSV.ИННПолучателя`
- `СтатусТранзита` ← `МаппингСтатусаТранзита(СтрокаCSV.СтатусПроцесса)`

> Перезапись существующих значений запрещена — только дозаполнение пустых.

### 4.2. Категория «НоваяТД» — создание нового документа ОПП

**Шапка нового документа:**
- `ВидОперации` ← `ТДФайл`
- `Дата` ← `СтрокаCSV.ДатаВыпуска` (или `ТекущаяДатаСеанса()` если пусто)
- `НомерГТД`, `НомерЭТД`, `ДатаОформления` ← `СтрокаCSV.РегНомерТД` / `ДатаВыпуска`
- `СуммаОбеспечения = 0`, `СуммаДокумента = 0`, `РазмерПоручительства = 0`
- `Организация` ← кешированная активная организация
- `ВалютаОбеспечения`, `ВалютаДокумента`, `ВалютаОплаты` ← кешированная валюта (RUB или первая активная)
- `СтатусОперации` ← `НеРассчитан`
- **НОВОЕ в v2:** `СтатусТранзита` ← `МаппингСтатусаТранзита(СтрокаCSV.СтатусПроцесса)`
- `Декларант`, `Перевозчик` ← lookup по точному наименованию + fallback по сокращению
- `Контрагент`, `ИННКонтрагента` ← из предложения
- `Комментарий` ← `СтрокаCSV.Комментарий`
- `Менеджер`, `Ответственный` ← текущий пользователь

**Строка ТЧ ДанныеДокументов:**
- `НомерГТД` ← `СтрокаCSV.РегНомерТД`
- `ТипУчета` ← `ТолькоТД`
- `ДатаОформления` ← `СтрокаCSV.ДатаВыпуска`
- `КоличествоУникальныхКодовТНВЭД` ← `СтрокаCSV.КоличествоКодовТНВЭД`

Документ записывается с `ОбменДанными.Загрузка = Истина` — как **черновик** (не проводится).

## 5. Маппинг СтатусПроцесса (CSV) → СтатусТранзита (1С)

Из реальных данных (живой тест 437 строк): в CSV встречаются только 2 значения,
но в перечислении 1С 13 — учитываем все известные синонимы:

| CSV «Статус процесса» | 1С «СтатусыТранзита» |
|------------------------|----------------------|
| Транзит завершен | ТранзитЗавершен |
| Транзит завершен с оговорками | ТранзитЗавершенСОговорками |
| Выпуск товара | ТоварВыпущен |
| Товар выпущен | ТоварВыпущен |
| Транзит разрешен | ТранзитРазрешен |
| Дополнение зарегистрировано | ДополнениеЗарегистрировано |
| Дополнение заключено | ДополнениеЗаключено |
| Дополнение отправлено | ДополнениеОтправлено |
| Средства разрезервированы | СредстваРазрезервированы |
| Товар не выпущен | ТоварНеВыпущен |
| Аннулировано специалистом | АннулированоСпециалистом |
| В заключении дополнения отказано | ВЗаключенииДополненияОтказано |

## 6. Поиск Контрагента (3 шага, приоритет сверху вниз)

```
1. EMAIL из комментария к ТД (#user@domain#)
   → Контрагенты.КонтактнаяИнформация.Представление = 'user@domain' (точно)
   → Партнёры.КонтактнаяИнформация → Контрагент партнёра
   → Контрагенты.КонтактнаяИнформация.ЗначенияПолей (JSON-fallback БСП 3.1+)

   ВАЖНО v2: переход с ПОДОБНО %email% на = (точное совпадение).
   ПОДОБНО давало false-positive когда email встречался как substring.
   Если пользователь хранит несколько email через разделитель — рассмотреть
   ' ' + email + ' ' границу.

2. ИНН получателя (col #101 CSV)
   → Контрагенты.ИНН = &ИНН (точное совпадение, ровно одна запись)

3. Подразделение Сигмы (col #1 CSV)
   → РегистрСведений.СоответствияПодразделенийКонтрагентам
   → batch-предзагружено картой до цикла (Perf #2)

Не нашлось — Контрагент = ПустаяСсылка(),
лог в ЖР с email/ИНН/подразделением для ручной привязки.
```

## 7. Поиск Декларанта/Перевозчика (новое в v2)

```
1. ПОЛНОЕ совпадение по Наименование (Справочники.Декларанты.НайтиПоНаименованию)
2. ЕСЛИ не нашли:
   а) Сокращаем по первому слову + первой букве имени
      «ИП СИДОРЕНКОВ ДМИТРИЙ АЛЕКСЕЕВ» → «ИП СИДОРЕНКОВ Д.А.»
      «"INTEGER" LLC» → «INTEGER LLC» (убрать кавычки)
   б) Точный поиск по сокращённой форме
3. ЕСЛИ ВСЁ ЕЩЁ не нашли:
   ПустаяСсылка() + лог «Декларант не сопоставлен» в ЖР

ВАЖНО: НЕ создаём декларантов автоматически — только сопоставление.
Создание новых элементов справочников — задача оператора.
```

## 8. Дубликаты НомерГТД в БД

В реальной БД 296 случаев когда один НомерГТД дублируется в ≥2 строках ТЧ
(всего из 1868 строк). Алгоритм матчера:

- Берёт **первую попавшуюся** строку ТЧ по дате документа (сортировка ASC).
- **НОВОЕ в v2:** при обнаружении дубля логирует в ЖР `WARN`:
  «Найдено N дублей НомерГТД=X, выбрана строка из документа Y от Z».
- Пользователь увидит warning в форме (счётчик «Дублей в БД: N»).

Это позволит увидеть проблему «зачем APIСигма создала дубли» и устранить
её отдельно — но текущий запуск не падает.
