Продолжаем работу по `td-spec-v1` (расширение Русский_Транзит для 1С:УТ в InfoBase5).

## КРИТИЧНО: используй ТОЛЬКО скиллы 1С (не пиши XML руками)

Это требование пользователя. Все XML-артефакты, валидация, сборка, загрузка — **через скиллы**, не через ручное редактирование. Перечень обязательных скиллов:

| Задача | Скилл | Когда |
|---|---|---|
| Создать/изменить форму | `/form-compile` → `/form-validate` | JSON DSL → XML |
| Создать/изменить метаданные (справочник/документ/перечисление/обработка) | `/meta-compile` или `/meta-edit` → `/meta-validate` | После любой правки .xml метаданных |
| Создать модуль | `/cfe-borrow` (для типовых) или `/cfe-patch-method` (правка типового) | Не редактировать модули типовых объектов вручную без маркеров `// Доработка START` |
| Валидация всего расширения | `/cfe-validate` | Перед загрузкой |
| Загрузка в базу | `scripts/load-extension.ps1` (НЕ через bash!) | После cfe-validate |
| Линт BSL | `/bsl-lint` | После любого изменения .bsl файла |
| Запуск тестов | METR MCP `run_all_tests` / `run_module_tests` | После загрузки расширения |
| Запросы к базе | `mcp__1c-mcp-kppzht__execute_query` (порт 6003) | Для верификации данных |
| Запуск кода в базе | `mcp__1c-mcp-kppzht__execute_code` | Для миграций и проверок |
| Метаданные | `mcp__1c-mcp-kppzht__get_metadata` | Проверка наличия объектов |

**НЕ ИСПОЛЬЗУЙ** `mcp__1c-mcp-client__*` — это HuggingFace proxy для удалённой базы клиента (1С:КА), не наша InfoBase5.

## Что нужно сделать (в порядке)

### Фаза 1: верификация загрузки расширения
Через `mcp__1c-mcp-kppzht__get_metadata` проверь что в InfoBase5 появились:
- `Перечисление.ВидыОперацийПоручительства` (новое)
- `Перечисление.СтатусыТранзита` со значением `ТаможенныйДосмотр` (новое значение)
- В `Документ.ОперацияПоПоручительству` реквизит `ВидОперации`
- `ОбщийМодуль.РусскийТранзитОбновлениеИБ`
- `Обработка.ЗагрузкаРееструТД`

Если чего-то нет — повторно загрузить через `scripts/load-extension.ps1` (предварительно удалив `ConfigDumpInfo.xml`).

### Фаза 2: миграция данных
Через `mcp__1c-mcp-kppzht__execute_query` посчитай документов с пустым ВидОперации:
```sql
ВЫБРАТЬ КОЛИЧЕСТВО(*) КАК Кол ИЗ Документ.ОперацияПоПоручительству КАК Оп
ГДЕ Оп.ВидОперации = ЗНАЧЕНИЕ(Перечисление.ВидыОперацийПоручительства.ПустаяСсылка)
```
Ожидание: 1572 до миграции.

Затем запусти миграцию через `mcp__1c-mcp-kppzht__execute_code`:
```bsl
Результат = РусскийТранзитОбновлениеИБ.ЗаполнитьВидОперацииДляСуществующих();
```

Повтори запрос — должно быть 0.

### Фаза 3: качество кода
- `/bsl-lint` по всем BSL расширения. Цель: 0 BLOCKER, 0 CRITICAL.
- YAxUnit тесты через METR MCP (`run_all_tests`)

### Фаза 4: проверка формы DataProcessor
- Открыть форму ЗагрузкаРееструТД, прочитать тестовый CSV Владимира (windows-1251)
- Проверить заполнение полей статистики (Всего, Комплекс, Новые ТД, Проблемы, Только обеспечение)
- Проверить заполнение Предложений (категория автозаполняется по правилам)
- Если есть playwright-mcp + веб-публикация — UI-тест через браузер

## Правила (НЕ нарушать)

1. **НЕ писать XML 1С руками** — только через скиллы compile/edit
2. **НЕ использовать `<!-- -->` в XML метаданных 1С** — ломает загрузку
3. **НЕ запускать `1cv8.exe` из bash** — только PowerShell-скрипты (bash искажает кириллицу)
4. **ВСЕГДА удалять `ConfigDumpInfo.xml`** перед загрузкой расширения
5. **Редактировать только `src/cfe/`** — `upload/` и `ut-ext/` это выгрузки
6. **Privileged=false** обязательно для CommonModules в CFE
7. **НЕТ `LineNumberLength`** в TabularSection
8. После любого изменения BSL → `/bsl-lint` (хук post-bsl-edit срабатывает автоматически)
9. После любого изменения формы → `/form-validate`
10. Перед коммитом → `/cfe-validate`

## Если возникнут проблемы

- **MCP `1c-mcp-kppzht` не подключился** → попроси пользователя запустить EPF MCP_Toolkit в InfoBase5 на порту 6003 (Встроенный сервер, формат TOON)
- **Форма не валидируется** → посмотри `version="2.20"` в Form.xml (баг скилла form-compile с подстановкой `$script:formatVersion`)
- **load-extension падает на LineNumberLength** → удали это свойство из TabularSection в .xml метаданных
- **load-extension падает на Privileged** → поставь `<Privileged>false</Privileged>` в CommonModule

Действуй проактивно, в auto mode. Не спрашивай «что дальше» — прорабатывай всю цепочку до конца, готовь следующие шаги сам. Read-only операции делай без подтверждения, destructive (запуск миграции на 1572 документа) — с подтверждением.
